# Durable publication/history — independent design preflight

Reviewer: Codex `test_claim_review`, read-only, separate from Root provider/bootstrap and qa store implementer. Read PLAN, prior durable proposal, current **Count providerf335**/wire/bootstrap/RPC host. No store code, SQL, processes, apps or product changes were executed. Only review notes/pins were written.

**Design is suitable for the bounded increment with the clarifications agreed below. This is design acceptance, not implementation/durability qualification.** No new defect is asserted from a coordinator proposal alone. Source and actual crash/CAS/RPC/browser evidence remain future gates.

## Current boundary and resolved design questions

The current f335 provider still creates Runner in its constructor, stores #definitions/#catalogs in memory, normalizes source paths through #owned(realpath) during publish, and needs an exact saved catalog SHA/version during execute. It includes Count/COUNTIF, so recovery must preserve its existing typed Countif scalar-slot rules and compiler, not reuse the older aff0 allowlist. Jobs/requests/cancellation/results remain process-local.

Trusted authority is external: storeId, grantId, canonical workDir, exact base-catalog digest, contract and approved executor/runtime identity. Store payload paths or self-reported hashes do not grant permission. The original two-top-level-file executor suggestion was too narrow; Root clarified that executorPin covers the **whole approved provider/native/source dependency roster** (compiler, graph/model helpers, Count/Filter/Sum/Lookup, wire, store and native dependencies), actual bootstrap hash and exact Node version/platform/arch. Check exact ordinary membership and actual bytes against trusted expected pins. Local hashes identify checked bytes, not authorship/authentication.

Root also clarified that **every publish commit includes its exact revision catalog snapshot**, including genesis0 persisted before Runner. catalog() returns validated committed latest; it does not invent an uncommitted discovery payload or expose a new ACK boundary. Thus the catalogue/discovery issue is resolved by design rather than deferred to guessed replay.

Store chain validation detects interior gaps/invalid records, but cannot detect a coherently valid prefix rollback or entirely removed terminal suffix without an external expected head. Root explicitly excludes that promise. Requested missing saved digest must still refuse. Do not advertise detection of every deleted acknowledged tail; an external trusted head/checkpoint would be required for that stronger claim.

## Necessary invariants for implementation review

1. **Before Runner/ready:** History open validates all committed numbered files, authority, chain and bounded lossless JSON, then calls trusted validateState(state,previousState) for every revision. A failing callback must propagate. Root's callback recomputes all admitted-definition/publication/descriptor/catalog identities, model/default/binding/compiler rules and immutable prefixes of definitions **and all catalogs**, exact base and revision progression. Only fully valid state hydrates private maps. It must not call public publish or fixture registry replay to reconstruct history. Avoid semantic source-file I/O during recovery.
2. **Creation is explicit:** create:true is owner first initialization; create:false refuses absent/empty history before Runner. A missing/corrupt history must not silently become an empty ephemeral provider. Existing opt-out ephemeral mode remains explicit and retains its old missing-history refusal. Root clarified that live refresh also refuses empty/regressed history; no silent rollback of cached metadata.
3. **Historical metadata vs current data:** Preserve admitted normalized absolute paths/order. Do not realpath historical inputs or require their existence during metadata load. For any originally relative/alias path, persist its admitted canonical mapping/context rather than resolving it under a new cwd. Fresh execute still realpaths inside the trusted grant and verifies current file/type/reader/source-copy hashes. Missing current file can fail execution and later retry after valid restoration without rewriting a descriptor/form. Current-input policy does not preserve old input/result bytes.
4. **Commit boundary:** Clone/validate complete snapshot and full canonical submitted publication/fingerprint before serialization. Closed state shapes and lossless JSON must prevent omitted undefined/function/nonfinite/sparse fields from becoming a different saved record. Stage unique/exclusive, write fully, fsync, close, then exclusive hardlink to the fixed expected next sequence. Never overwrite/unlink a competing acknowledged destination or fall back to destructive rename. Keep pending stages separate and never auto-promote/delete them.
5. **CAS and stale state:** DirectoryHistory.read/commit must validate actual current head, not only cached state. Same expected sequence has at most one publication winner; loser is explicit. A provider retry refreshes metadata and revalidates its intended append against that new immutable prefix, rather than committing its stale full snapshot and losing another ACK. On metadata refresh swap only fully validated definitions/catalog maps; preserve live #jobs/#requests/child handles and the immutable record captured by an existing job.
6. **Lost ACK is exact:** If final link succeeded and caller lost the response, new readback recognizes that record. Identical **complete canonical submitted** fingerprint may return its stored descriptor/receipt without new revision. Different payload at the same ID/version refuses, including metadata/units/defaults/array-order differences that a definition-only hash might ignore. Do not regenerate a descriptor/ACK from current latest catalog and call it the original receipt. Canonical object-key order can be insignificant; semantic array order stays significant.
7. **Reentry/closed/shutdown:** A metadata-operation gate must cover validation, store callbacks, commit and hydration; no public method sees half-updated maps. Define provider close-start admission semantics before await. A committed-but-unacknowledged operation is a lost-ACK case, not justification for deleting committed files. **Metadata corruption/missing history must not prevent cancellation/status/close of an already owned job/child**: fail new work closed while preserving cleanup ownership. There is no durable job/request replay or automatic resurrection.
8. **Bounds without data loss:** Enforce16MiB per record,128MiB total and256 commits in both read/commit paths, before allocating/ACKing an over-limit state. Specify whether total means committed serialized bytes and how pending stages are reported; do not imply pending disk use is garbage-collected/bounded if it is only ignored. Limit refusal must preserve acknowledged history and avoid silent dropping of old snapshots to make room. No fsync/directory behavior is promoted to power-loss durability on Windows.

These are required implementation/review contracts, not claims that an uninspected module already satisfies them. No new store close() API is imposed: if the store holds no persistent resources, provider may own the closed gate; actual methods must remain honest.

## Finite evidence gates

- **Pure/owned FS first:** wrong authority/base/executor/source-membership; malformed/lossy JSON; missing interior commit; corrupt chain/body; coherently changed latest old-definition/default/unit/catalog that violates the predecessor prefix; bounds; write/fsync/link failure. Deliberately removed validator/immutable-prefix guard must be caught by a separately reasoned oracle. Whole-chain coherent rewrite/valid-prefix rollback is not called authenticated tamper detection.
- **Actual metadata-only processes:** two writers start at the same parent, one winner or explicit loser; retry conserves all ACKs. Stop own child before publication and after link/before ACK. Fresh process reads old or newly committed state accordingly; exact retry does not duplicate, changed same-version payload refuses. Keep pending evidence. No foreign process or policy changes.
- **Actual RPC/native:** parentA publishV1/save exact pinned configured form/addV2/close; parentB with same external store/grant/executor and **no publication registry replay** opens exact old catalog and runs a fresh request. Verify types/empty/false/zero/NULL/units/coverage/provenance. Changed current authorized bytes produce a new captured hash/result; missing file→refusal→restore retry preserves metadata/form. Cancel/error/retry and all owned child closure remain separate from metadata restart.
- **Actual reference browser:** same physical Save/Open values/pins through a genuinely new provider parent, not another object in one process. Browser/server/service/consumer and native-worker evidence are labelled separately from actual UI Builder designer adoption. Existing ephemeral mode is a retained control, not fallback after durable corruption.

No main/preload/Electron/Lock/PIN/Docs export changes are needed or authorized by this metadata design. The affected cross-boundaries are trusted bootstrap→store→provider→Runner/RPC and shutdown; prior wire2/saved-form reference semantics remain unchanged unless an explicit new incompatibility decision is reviewed.
