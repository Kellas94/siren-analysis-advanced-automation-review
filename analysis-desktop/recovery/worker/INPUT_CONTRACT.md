# Private worker/catalog contract

This is a breaking private correction, version 2.0.0-private.1. `siren.worker-catalog/2` is separate from `siren.analysis.execution-receipt/2` and the histogram UI receipt. No automatic migration from the author's catalog is provided. Historical author code/reports/storage are preserved under historical-author and are not current evidence.

Use one RecoveryOrchestrator with an explicit absolute owned baseDir. Await recover() to completion before exposing capture, execution, cleanup or shutdown. Recovery is a startup prerequisite; overlap of shutdown with cold hashing is outside qualification. Capture and execution share a single active slot. Shutdown aborts and waits capture or cancels and waits execution, and awaits owned child close. After shutdown the orchestrator refuses new work.

captureInput(file,{nodeId,signal}) streams an owned immutable-at-capture copy, hashes it and persists its metadata. Sequential input capture is not an atomic dataset transaction. The original's later state is unknown. executeJob({jobId,inputs,compiledQuery}) uses registered snapshot identity; compileSingleInputQuery/compileJoinQuery from the pinned data API generate the bounded supported plans. Arbitrary SQL, general workflow graphs, dynamic readers and native result streaming are outside this API. Results capture at most 50 rows; complete output/source/null counts are separate full queries. TRUNCATED describes the captured rows, never the full aggregation population. Exact JSON strings retain DECIMAL/BIGINT values and VARCHAR identity.

getActiveOperation() returns {jobId,attemptId,sessionToken}. cancelJob requires this exact object identity tuple; a jobId alone or an old attempt returns requested:false. Parent cancellation marks the matching request before IPC; worker independently validates the tuple. retryJob(jobId) restores the last persisted compiled request and exact retained snapshots, with a new attempt number and session token. Actual worker PID is recorded before submission. Child callbacks are bound to their own process/generation; replacement waits for close.

The parent imports snapshot/compiler/verifier modules directly. DuckDB queries run in the child. The child verifies actual input hashes/bytes before and after execution and checks cancellation after awaited work. Receipt/rows are verified before catalog SUCCESS, saved in hash-named files and revalidated from disk on recovery. Missing/corrupt SUCCESS evidence becomes INVALID. Receipt hashes prove internal integrity, not external authenticity.

Catalog writes use an exclusive short-lived writer lock, revision comparison, temporary file fsync and rename. Stale writers refuse and require reopening. Recovery refuses live, unknown or missing recorded process identity and unknown lease ownership; it never kills a PID found in catalog. Dead attempts reconcile to INTERRUPTED. Orphan cleanup considers only the recovery-discovered owned sealed files, rechecks revision and registrations under the same lock, and never sweeps all staging files.

Limits: no authentication against a caller rewriting catalog and recomputing digests; no hard filesystem immutability against another program; no multi-host or general concurrent-controller service. Abandoned writer locks require explicit diagnosis; there is no automatic lock stealing. Power loss/directory fsync is not qualified. Internal Maps/managers are implementation details, not public cleanup or tamper-proof APIs. No installed SIREN or Electron qualification, no UI integration is claimed by this package.
